## 3. 评分系统的关键结论

1. 评分体系由“可配置方案、AI分项评价、程序计分、教师复核”组成。
2. 该DSE参考方案满分103：内容40、表达30、结构20、标点字体10、错别字3。
3. 品第、等级值、维度分数分开保存；先评定，再执行规则。
4. 字数不足限制内容品第上限，不默认另扣总分。550—649字内容上限仍为上上。
5. 同时命中多个同维度上限时，取更严格值，避免重复处罚。
6. 错别字独立计分，重错不重复计算。OCR识别错误不能计作学生错字。
7. 字迹评价需要原图，不能仅根据识别文本或识别率判断。
8. 通用维度之外，还需要本题审题要求、合理诠释范围及入品依据。
9. 校本适配需要修改档位描述、样例和题目要求，不能只调整权重。
10. 官方模板保留原版；校本派生标明修改，发布任务时固定评分快照。
11. 原稿、AI初评、教师修订、正式发布结果和模型版本分别留痕。
12. 不直接把不同学校方案的分数横向排名，也不由单篇作文推算DSE总科等级。

待确认口径包括：恰好300字的区间重叠；标题、英文、数字、空格、涂改等计数字段；同一错字的归并规则。系统不得将自行猜测包装成官方要求。

## 4. 最终确认的提交方式

仅保留两种入口：

### 学生拍照提交

老师发布任务 → 学生进入任务 → 拍照／选择照片 → 检查清晰度与页序 → 确认提交 → 进入统一批改流程。

通过学生账号和任务确定身份，不需要再次猜测照片属于哪个学生。

### 老师批量上传

选择任务与班级 → 上传照片或扫描文件 → 作文分组 → 学生匹配 → 处理异常和重复 → 确认收稿 → 进入统一批改流程。

一个文件不必然等于一名学生；一个学生可能有多页。无法确认归属的稿件先待确认，不生成正式学生成绩。老师上传并匹配后，学生端显示已收稿，无需重复拍照。

## 5. 重写范围的调整记录

早期讨论曾提出“批改后订正／同题重写”，随后用户明确要求暂时去掉。

当前版本：

- 不提供同题重写、二次创作提交、稿件进步对比和重写后评分。
- 不提供在线订正提交及订正验收工作流。
- 批改发布后，学生查看反馈，本次任务完成。
- 可以提供修改建议，但不要求再次交稿。

保留提交纠错：补齐缺页、替换模糊图片、纠正页序和学生归属。

保留原稿评分复核：老师修改批注或评分，必要时对同一原稿重评，并保留记录。提交纠错和重评不等于学生重写。

## 6. 角色与两端分工

| 角色 | 主要职责 | 建议使用端 |
|---|---|---|
| 学校管理员 | 教学组织、账号与权限 | Web后台 |
| 教学负责人 | 评分方案、审核与校准 | Web后台 |
| 任课教师 | 任务、收稿、教师复核、发布 | Web后台 |
| 学生 | 拍照提交、查看状态与正式反馈 | App |
| AI与规则服务 | 识别、初评、确定性计分 | 系统服务，无独立发布权限 |

教师移动工作区仅作为可选增强，首期不默认复制全部后台功能。学校管理员不因管理账号而自动具有改分权限。

后台主要菜单：工作台、作文任务、收稿管理、批改中心、成绩与反馈、评分标准、教学组织、学情分析、评分质量、学校设置。各角色按权限裁剪。

学生App底部菜单：作文任务、消息、我的。拍照提交置于具体任务内，成绩从已发布任务进入。
